## 1. Модель данных: новые поля `site_materials`

Миграция идёт в проект ATS (`byerqfuuprmmykncjqms`). Все поля nullable, поэтому существующие 41 материал продолжают работать без изменений.

| Поле | Тип | Назначение |
|---|---|---|
| `rubric` | `text` + check (`salary`, `pulse`, `practice`, `case`, `regulation`, `annual`) | Рубрика. **Если задана – материал попадает в раздел «Аналитика»**. С 29.10.2026 `practice` в интерфейсе не используется: практические статьи – в «Полезных материалах» без рубрики (в базе значение ещё разрешено) |
| `industries` | `text[]` | Отрасли из справочника (§1.1) |
| `author_key` | `text` | `akmal`, `anna`, `team`, … – данные автора в коде (§3.3) |
| `key_figures` | `jsonb` | `[{"value":"45 дней","label":"средний срок закрытия позиции руководителя"}, …]`, 3–5 штук |
| `methodology` | `text` | Источник данных и метод (1–3 предложения) |
| `sample_size` | `text` | «312 вакансий», «87 ответов» – текстом, чтобы можно было писать «n = 87» |
| `period` | `text` | «январь – сентябрь 2026» |
| `gated_pdf_url` | `text` | Ссылка на PDF. Если задана – вместо обычного CTA показывается форма скачивания |
| `cta` | `text` + check (`consult`, `download`, `subscribe`) | Какой CTA показать в конце; по умолчанию `consult` |
| `seo_title` | `text` | Если пусто – как сейчас (`headline()` из `api/article.js`) |
| `seo_description` | `text` | Если пусто – как сейчас (`clip(...)`) |
| `og_image` | `text` | Если пусто – `media_url`, иначе `og-cover.png` |

`slug` отдельным полем **не вводим**: адрес по-прежнему транслитерируется из заголовка + 8 символов id (`articleSlug`). Схема уже работает, а при смене заголовка выполняется 301-редирект.

`lang` и `translation_of` уже есть – переключатель RU/EN для переводов работает «из коробки».

### 1.1 Справочник отраслей (v1)

`general` (все отрасли), `it`, `finance` (банки, финтех, страхование), `retail` (ритейл, FMCG, дистрибуция), `manufacturing`, `construction` (стройка, девелопмент), `logistics`, `pharma` (фарма, медицина), `telecom`, `horeca`, `energy` (энергетика, горнодобыча), `services` (B2B-услуги, консалтинг), `public` (госсектор, международные организации).

Хранится константой в одном месте (новый `api/_taxonomy.js` + копия для браузера) с подписями на RU / EN / UZ.

### 1.2 Пример миграции

```sql
alter table site_materials
  add column rubric text check (rubric in ('salary','pulse','practice','case','regulation','annual')),
  add column industries text[] default '{}',
```

## 2. Страница раздела `/analytics`

**Файлы:** `analytics.html`, `analytics-en.html`, `analytics-uz.html` – копия каркаса `resources*.html` (шапка, футер, стили, `hc-analytics.js`, `hc-crm.js`).

**Адреса** (в `vercel.json`, по образцу существующих):
- `/analytics` → `/analytics.html`
- `/analytics/en`, `/insights` → `/analytics-en.html`
- `/analytics/uz` → `/analytics-uz.html`

**Содержимое:**
1. Hero: заголовок («Аналитика рынка труда Узбекистана» / «Uzbekistan Labour Market Insights»), одна строка про источники данных, кнопка «Подписаться в Telegram».
2. **Флагманский блок**: последний материал с `rubric in ('annual','salary')` и `gated_pdf_url` – крупная карточка «Скачать отчёт».
3. Фильтры-чипы: рубрика (все / зарплаты / пульс рынка / практика найма / кейсы / регулирование) + выпадающий список отрасли. Состояние фильтра сохраняется в URL (`?rubric=pulse&industry=it`) – этими ссылками можно делиться в рассылке.
4. Сетка карточек: обложка, бейдж рубрики, заголовок, лид, дата, автор.
5. Внизу – подписка: Telegram + форма «Получать обзоры на email» (через `submit_lead`, источник «Подписка на аналитику»).

**Выборка:** `site_materials?published=eq.true&rubric=not.is.null`. Логика выбора языковой версии – как в `resources.html` (`loadMaterials` → `pick`).

**`resources*.html`** продолжает показывать все материалы, включая аналитику, с бейджем рубрики. Ничего не скрываем, чтобы не терять внутренние ссылки.

**Навигация:** пункт «Аналитика» в меню всех страниц, рядом с «Полезные материалы». Меню вписано в каждый HTML-файл, поэтому его нужно поправить во всех страницах на трёх языках, а для статей – ещё и в `tools/build_article_shell.py` (с пересборкой `api/_shell*.html`).

**Sitemap:** добавить `["analytics", "0.8"]` в `PAGES` (`api/_lib.js`).

## 3. Страница статьи: доработки `api/article.js`

Касается только материалов с `rubric`; остальные статьи выглядят как сейчас.

### 3.1 Шапка
- Бейдж рубрики вместо «Статья», ссылка на `/analytics?rubric=…`.
- Хлебные крошки: Главная / Аналитика / [статья] (сейчас – «Полезные материалы»). То же в `BreadcrumbList`.
- Под датой – автор: фото, имя, должность, ссылка на LinkedIn.

### 3.2 Блок «Ключевые цифры»
Сразу после лида, до основного текста. 3–5 карточек: крупное число (фирменный горчичный `#c69a2e`) и подпись. На мобильном – 2 в ряд или горизонтальный скролл. Вёрстка – в `article.css`, префикс `.ar-kf-`.

### 3.3 Автор
Константа в `api/_lib.js`:

```js
const AUTHORS = {
  akmal: { ru: "Акмаль Саипов", en: "Akmal Saipov", role: { ru: "Сооснователь", en: "Co-founder" },
           photo: "/team-akmal-saipov.png", url: "https://www.linkedin.com/in/akmal-saipov-38b144153/" },
  anna:  { ru: "Анна Джу", en: "Anna Dju", role: { ru: "Генеральный директор и соучредитель", en: "CEO & Co-founder" },
           photo: "/team-anna-dzhu.png", url: "https://www.linkedin.com/in/anna-dju-122983211/" },
  team:  { ru: "Аналитический центр Human and Capital", en: "Human and Capital Research", … },
};
```
Должности уточнить. В schema.org `author` → `Person` с `sameAs: [LinkedIn]` (сейчас там `Organization`). Для `team` остаётся `Organization`.

### 3.4 Блок «Методология»
В конце текста, до CTA: серая плашка «Методология · Период · Выборка». Если у материала с рубрикой `salary`, `pulse` или `annual` поле `methodology` пустое, админка не даёт его опубликовать (§5).

### 3.5 CTA (вместо текущего единого `ar-cta`)
| `cta` | Заголовок | Кнопка |
|---|---|---|
| `consult` | «Обсудим ваш найм?» | «Обсудить найм» → форма заявки (`/recruitment.html#contact`, как сейчас) |
| `download` | «Получите обзор по вашей отрасли» | Форма скачивания (§4) |
| `subscribe` | «Новые обзоры – раз в месяц» | «Подписаться в Telegram» + email |

Кроме того, в каждой статье с рубрикой под текстом стоит небольшая плашка «Подписаться на канал аналитики в Telegram», независимо от `cta`.

### 3.6 SEO
`seo_title` / `seo_description` / `og_image` – если заданы, используются вместо автоматических. `og:type=article`, `article:section` = рубрика, `article:tag` = отрасли.

## 4. Скачивание отчёта (gated PDF)

### 4.1 Форма
Встраивается в статью-анонс отчёта (`gated_pdf_url` задан).

| Поле | Обязательное |
|---|---|
| Имя | да |
| Компания | да |
| Должность | да |
| Email | да (на него же дублируется ссылка) |
| Телефон | **нет** – «для приглашения на презентацию отчёта» |
| Согласие на обработку ПДн | да (существующий `consentMarkup`) |
| honeypot | – (существующий) |

Отказались от обязательного телефона: для отчёта это лишний барьер. Звонок всё равно возможен, если человек оставил телефон или по email.

### 4.2 Отправка
Новая функция в `hc-crm.js`, рядом с `leadAttempt`:

```js
c.staffly.rpc("submit_lead", {
  p_name, p_email, p_phone,
  p_message: "Компания: …\nДолжность: …\nОтчёт: <title>",
  p_service: null,
  p_source: "Отчёт: <title> | " + location.pathname + utmSuffix(),
  p_locale: locale(), p_consent: true
})
```

- Сделка падает в Staffly в «Новый лид» с понятным источником – отдел продаж видит, какой отчёт скачан.
- `utmSuffix()` – `utm_source/medium/campaign` из URL (или из `sessionStorage`, если человек зашёл по UTM и перешёл на другую страницу), чтобы в CRM было видно, из TG, LinkedIn или рассылки пришёл лид.
- После успеха: форма сменяется кнопкой «Скачать PDF» (ссылка на `gated_pdf_url`), цель `report_download`. Повторно скачать с этого устройства можно без формы (флаг в `localStorage`).

### 4.3 Где лежит PDF
Supabase Storage проекта ATS, бакет `reports`, публичный. Ссылка содержит случайную часть (`/reports/2027-annual-8f3k2.pdf`).

Это «мягкий» гейт: ссылку можно переслать. Для B2B-отчётов это нормально, пересылка – тоже охват. Строгий вариант (подписанная ссылка на 24 часа через serverless-функцию) возможен, но на старте он не нужен.

Внутри PDF – CTA и контакты (отчёт пересылают коллегам).

### 4.4 Почему не форма на отдельной странице
Анонс отчёта – это и есть его страница: превью, ключевые цифры, оглавление, форма. Одна страница вместо двух – одна точка для SEO и для ссылок в рассылке.

- PDF лежит в репозитории сайта (`/reports/<slug>-<случайная часть>.pdf`, заголовок `X-Robots-Tag: noindex`), а не в Supabase Storage: так проще и бесплатно; собирает `tools/build_report.py` из агрегатов `tools/reports/*.json`.

**30.10.2026 – PDF только по запросу** (решение: «чтобы выходили на нас»). Мгновенного скачивания нет: после отправки формы – «Пришлём отчёт на почту в течение рабочего дня, менеджер свяжется с вами». В Staffly – сделка с источником «Запрос отчёта (PDF): <заголовок> | путь | utm» и сообщением «ЗАПРОС ОТЧЁТА (PDF): …, что сделать: отправить PDF и связаться». Цель – `report_request` (вместо `report_download`). PDF с сайта убран (`/reports/…` – 404), `tools/build_report.py` пишет файл в `~/Downloads`. `gated_pdf_url` – необязательная внутренняя ссылка для менеджера, на сайт и в `/api` не выводится (но читается через открытый REST `site_materials` – публичные ссылки туда не класть).
